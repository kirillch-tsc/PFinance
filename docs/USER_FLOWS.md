# PFinance: навигация и пользовательские сценарии

Документ описывает продуктовую навигацию и последовательности действий пользователя. Он не определяет визуальный дизайн, программные компоненты, маршруты или реализацию и не добавляет функций сверх согласованных документов PFinance.

## Общие принципы

- Основной сценарий: быстро добавить операцию и сразу увидеть обновлённое состояние финансов.
- Основные разделы: «Главная», «Операции», «Бюджет» и «Настройки».
- Переход между основными разделами не должен создавать или изменять финансовые данные.
- Балансы, бюджетные показатели и cash flow пересчитываются из сохранённых операций.
- Несохранённые данные не должны исчезать без предупреждения пользователя.
- После успешного действия пользователь возвращается в контекст, из которого начал сценарий, если для конкретного сценария не установлено иное.

## 1. Навигация

### Мобильная нижняя панель

На мобильном устройстве нижняя панель обеспечивает постоянный переход между четырьмя основными разделами:

1. «Главная».
2. «Операции».
3. «Бюджет».
4. «Настройки».

Правила поведения:

- текущий раздел однозначно обозначен;
- повторный выбор текущего раздела возвращает на его основной экран;
- переход в другой раздел сохраняет выбранный период только там, где это не меняет смысл данных;
- открытая форма с несохранёнными изменениями не закрывается без проверки;
- нижняя панель не содержит дополнительных разделов;
- создание операции остаётся отдельным основным действием, а не пятым разделом навигации.

### Десктопная навигация

На десктопе доступны те же четыре раздела в том же порядке и с теми же названиями. Отличается только размещение навигации; информационная архитектура и смысл переходов не меняются.

Правила поведения:

- текущий раздел однозначно обозначен;
- переход между разделами ведёт на основной экран выбранного раздела;
- дополнительные действия не добавляются только из-за большего размера экрана;
- открытая форма и несохранённые изменения обрабатываются так же, как на мобильном устройстве.

### Переходы между четырьмя разделами

#### Главная

С Главной пользователь может:

- перейти в «Операции» к полному списку;
- открыть создание операции;
- открыть одну из последних операций;
- перейти в «Бюджет» или открыть конкретный бюджет;
- перейти в «Настройки» к конкретному счёту;
- выбрать любой основной раздел через навигацию.

#### Операции

Из раздела «Операции» пользователь может:

- открыть создание операции;
- открыть существующую операцию;
- перейти в настройки счетов или категорий, если без них нельзя завершить ввод;
- выбрать любой основной раздел через навигацию.

#### Бюджет

Из раздела «Бюджет» пользователь может:

- открыть конкретный бюджет;
- создать или отредактировать бюджет;
- открыть список расходов, вошедших в бюджет;
- открыть отдельную расходную операцию;
- перейти в настройки категорий, если нет подходящей категории расходов;
- выбрать любой основной раздел через навигацию.

#### Настройки

Из раздела «Настройки» пользователь может:

- открыть счета, категории, валюты, резервное копирование или прочие настройки;
- создать или изменить счёт;
- создать или изменить категорию;
- перейти к операциям выбранного счёта или категории;
- выбрать любой основной раздел через навигацию.

### Кнопка «Добавить операцию»

- На Главной и основном экране «Операции» действие доступно напрямую.
- В контексте конкретного бюджета доступно создание расхода с заранее выбранной категорией бюджета; пользователь проверяет остальные поля перед сохранением.
- Если нет активного счёта, действие ведёт к созданию счёта с объяснением причины.
- Если для дохода или расхода нет активной категории нужного вида, форма предлагает перейти к созданию категории.
- После возврата из создания счёта или категории ранее введённые данные операции сохраняются, если это возможно.
- Открытие формы само по себе не создаёт операцию.

### Возврат назад

- Возврат назад ведёт на предыдущий экран внутри текущего пользовательского сценария.
- Из просмотра или редактирования операции пользователь возвращается к списку, Главной или бюджету, откуда операция была открыта.
- Из карточки бюджета пользователь возвращается к списку бюджетов с сохранённым выбранным периодом.
- Из вложенного раздела настроек пользователь возвращается на основной экран «Настройки».
- Если предыдущий контекст недоступен, пользователь возвращается на основной экран соответствующего раздела.
- Возврат назад не отменяет уже успешно сохранённые изменения.

### Несохранённые изменения

Несохранёнными считаются данные формы, которые отличаются от исходного состояния.

При возврате назад, переходе в другой раздел или закрытии формы:

1. Если изменений нет, переход выполняется сразу.
2. Если изменения есть, пользователь получает выбор:
   - продолжить редактирование;
   - выйти без сохранения.
3. Выбор продолжить оставляет пользователя в форме со всеми введёнными значениями.
4. Выход без сохранения возвращает в предыдущий контекст и не изменяет данные.

Автоматическое сохранение финансовых данных не предполагается. Ошибка сохранения не считается отменой: введённые значения остаются доступны для исправления или повторной попытки.

## 2. Основные сценарии

### 2.1. Первый запуск

#### Начальное состояние

- В приложении нет счетов, категорий, операций и бюджетов.
- Пользователь находится на Главной.

#### Шаги пользователя

1. Пользователь видит объяснение, что для начала учёта нужен первый счёт.
2. Выбирает действие создания счёта.
3. После создания счёта получает предложение создать необходимые категории.
4. После создания хотя бы одной категории дохода или расхода может перейти к добавлению первой операции.

#### Проверки

- Пустое состояние не показывает фиктивные финансовые данные.
- Создание операции недоступно до появления активного счёта.
- Для дохода или расхода требуется активная категория соответствующего вида.

#### Успешный результат

- Создан активный счёт.
- Создана хотя бы одна категория для планируемого типа первой операции.
- Пользователь может добавить операцию и увидеть состояние финансов.

#### Ошибки и восстановление

- При ошибке создания счёта введённые данные сохраняются, доступна повторная попытка.
- Пользователь может отменить настройку и вернуться на пустую Главную.
- Если счёт создан, а категории нет, счёт сохраняется; пользователь может продолжить настройку позже.

### 2.2. Создание первого счёта

#### Начальное состояние

- Счетов нет.
- Сценарий открыт с Главной или из «Настройки → Счета».

#### Шаги пользователя

1. Выбирает «Создать счёт».
2. Вводит название.
3. Выбирает валюту.
4. Указывает начальный баланс и его дату.
5. Проверяет данные.
6. Сохраняет счёт.

#### Проверки

- Название непустое после удаления пробелов по краям.
- Валюта является допустимым кодом валюты.
- Начальный баланс является корректным денежным значением.
- Дата начального баланса заполнена.

#### Успешный результат

- Создан активный счёт.
- Его начальный баланс отображается на Главной и в списке счетов.
- Пользователю становится доступно создание операции при наличии подходящей категории.

#### Ошибки и восстановление

- Некорректные поля отмечаются до сохранения.
- При ошибке сохранения введённые значения остаются в форме.
- Отмена возвращает на исходный экран без создания счёта.

### 2.3. Создание категорий

#### Начальное состояние

- Пользователь находится в «Настройки → Категории» либо пришёл из формы операции или бюджета.

#### Шаги пользователя

1. Выбирает создание категории.
2. Выбирает вид: доход или расход.
3. Вводит название.
4. Сохраняет категорию.
5. При необходимости повторяет сценарий для другого вида.

#### Проверки

- Название непустое после удаления пробелов по краям.
- Среди активных категорий того же вида нет категории с таким названием.
- Вид категории выбран до сохранения.

#### Успешный результат

- Создана активная категория выбранного вида.
- Категория доступна для новых операций соответствующего типа.
- Категория расходов доступна при создании бюджета.

#### Ошибки и восстановление

- Дублирующее или пустое название не сохраняется; пользователь может исправить его.
- При ошибке сохранения введённые данные не сбрасываются.
- При отмене пользователь возвращается в исходный контекст.
- Если категория создавалась из формы операции или бюджета, после сохранения пользователь возвращается в эту форму, а новая категория становится доступной для выбора.

### 2.4. Добавление расхода

#### Начальное состояние

- Есть хотя бы один активный счёт и одна активная категория расходов.
- Пользователь открывает создание операции с Главной, из «Операций» или из карточки бюджета.

#### Шаги пользователя

1. Выбирает тип «Расход».
2. Вводит сумму.
3. Выбирает счёт-источник.
4. Выбирает категорию расходов.
5. Проверяет дату и время.
6. При необходимости добавляет комментарий.
7. Сохраняет операцию.

#### Проверки

- Сумма больше нуля.
- Счёт активен.
- Категория активна и имеет вид `expense`.
- Валюта суммы определяется валютой счёта.
- Дата операции не раньше даты начального баланса счёта.

#### Успешный результат

- Расход появляется в списке операций.
- Баланс счёта и общий баланс уменьшаются.
- Расходы за соответствующий период увеличиваются.
- Cash flow за период уменьшается.
- Потраченное по подходящему бюджету увеличивается, остаток уменьшается.

#### Ошибки и восстановление

- Ошибочные поля можно исправить без повторного заполнения формы.
- При ошибке сохранения данные остаются в форме, доступна повторная попытка.
- Если нет подходящей категории, пользователь может создать её и вернуться к операции.
- Отмена возвращает в исходный контекст без пересчётов.

### 2.5. Добавление дохода

#### Начальное состояние

- Есть хотя бы один активный счёт и одна активная категория доходов.
- Пользователь открыл создание операции.

#### Шаги пользователя

1. Выбирает тип «Доход».
2. Вводит сумму.
3. Выбирает счёт-получатель.
4. Выбирает категорию дохода.
5. Проверяет дату и время.
6. При необходимости добавляет комментарий.
7. Сохраняет операцию.

#### Проверки

- Сумма больше нуля.
- Счёт активен.
- Категория активна и имеет вид `income`.
- Валюта суммы определяется валютой счёта.
- Дата операции не раньше даты начального баланса счёта.

#### Успешный результат

- Доход появляется в списке операций.
- Баланс счёта и общий баланс увеличиваются.
- Доходы и cash flow соответствующего периода увеличиваются.
- Бюджеты расходов не меняются.

#### Ошибки и восстановление

- Ошибочные поля можно исправить без потери остальных данных.
- При ошибке сохранения доступна повторная попытка.
- Если нет категории дохода, пользователь может создать её и вернуться к операции.
- Отмена не изменяет финансовые данные.

### 2.6. Перевод между счетами

#### Начальное состояние

- Есть не менее двух активных счетов в одной валюте.
- Пользователь открыл создание операции.

#### Шаги пользователя

1. Выбирает тип «Перевод».
2. Вводит сумму.
3. Выбирает исходный счёт.
4. Выбирает целевой счёт.
5. Проверяет дату и время.
6. При необходимости добавляет комментарий.
7. Сохраняет перевод.

#### Проверки

- Сумма больше нуля.
- Оба счёта активны.
- Исходный и целевой счета различаются.
- Валюты счетов совпадают.
- Дата перевода не раньше даты начального баланса обоих счетов.
- Категория для перевода отсутствует.

#### Успешный результат

- Перевод появляется в списке операций.
- Баланс исходного счёта уменьшается.
- Баланс целевого счёта увеличивается на ту же сумму.
- Общий баланс, доходы, расходы, бюджеты и cash flow не меняются.

#### Ошибки и восстановление

- Один и тот же счёт нельзя сохранить как исходный и целевой.
- Счета разных валют нельзя использовать в одном переводе.
- Если подходящей пары активных счетов нет, пользователь получает объяснение и может перейти к созданию счёта.
- При ошибке сохранения введённые данные остаются доступными.
- Отмена возвращает в исходный контекст без изменения балансов.

### 2.7. Создание бюджета

#### Начальное состояние

- Есть активная категория расходов.
- Пользователь находится в разделе «Бюджет» или пришёл из его пустого состояния.

#### Шаги пользователя

1. Выбирает «Создать бюджет».
2. Выбирает категорию расходов.
3. Указывает начало и конец периода.
4. Выбирает валюту.
5. Вводит лимит.
6. Сохраняет бюджет.

#### Проверки

- Выбрана активная категория вида `expense`.
- Лимит неотрицательный.
- Конец периода не раньше начала.
- Для этой категории нет бюджета с пересекающимся периодом.
- Валюта является допустимой.

#### Успешный результат

- Бюджет появляется в списке выбранного периода.
- Потраченное рассчитывается по существующим расходам соответствующей категории, валюты и периода.
- Остаток и доля использования рассчитываются автоматически.

#### Ошибки и восстановление

- При пересечении периодов показывается конфликтующий бюджет; пользователь может изменить период.
- Если нет категории расходов, пользователь может создать её и вернуться в форму бюджета.
- При ошибке сохранения данные формы сохраняются для повторной попытки.
- Отмена возвращает к списку бюджетов с прежним периодом без создания записи.

### 2.8. Редактирование операции

#### Начальное состояние

- Существующая операция открыта с Главной, из списка операций или из карточки бюджета.

#### Шаги пользователя

1. Выбирает редактирование.
2. Изменяет необходимые поля.
3. Проверяет предупреждение о пересчёте финансовых показателей.
4. Сохраняет изменения.

#### Проверки

- Применяются те же ограничения, что при создании выбранного типа операции.
- Для перевода проверяются разные счета и одинаковая валюта.
- Категория соответствует типу дохода или расхода.
- Дата допустима для всех связанных счетов.

#### Успешный результат

- Операция содержит новые значения.
- Старое влияние операции удаляется из расчётов.
- Новое влияние применяется к балансам, доходам, расходам, cash flow и бюджетам.
- Пользователь возвращается туда, откуда открыл операцию, и видит обновлённые данные.

#### Ошибки и восстановление

- Некорректное изменение не сохраняется; остальные введённые значения остаются.
- Если операция уже изменена или удалена в другом сеансе, показывается актуальное состояние и предлагается повторить редактирование.
- При ошибке сохранения исходная операция остаётся неизменной.
- Отмена возвращает в исходный контекст без пересчёта.

### 2.9. Удаление операции

#### Начальное состояние

- Существующая операция открыта для просмотра или редактирования.

#### Шаги пользователя

1. Выбирает удаление.
2. Проверяет описание операции и предупреждение о пересчёте.
3. Подтверждает удаление или отменяет действие.

#### Проверки

- Перед удалением однозначно показана выбранная операция.
- Удаление не выполняется без явного подтверждения.
- Повторное подтверждение уже удалённой операции не создаёт дополнительных изменений.

#### Успешный результат

- Операция исчезает из списка.
- Её влияние исключается из балансов счетов и общего баланса.
- Доходы, расходы и cash flow соответствующего периода пересчитываются.
- Связанные бюджеты пересчитываются.
- Пользователь возвращается в исходный список, на Главную или в карточку бюджета.

#### Ошибки и восстановление

- При отмене операция и расчёты не меняются.
- При ошибке удаления операция остаётся доступной, пользователь может повторить попытку.
- Если операция уже удалена, пользователь возвращается в исходный контекст с сообщением об актуальном состоянии.

### 2.10. Закрытие счёта

#### Начальное состояние

- Существующий активный счёт открыт в «Настройки → Счета».
- Закрытие означает перевод счёта в неактивное состояние, а не удаление истории.

#### Шаги пользователя

1. Выбирает действие закрытия счёта.
2. Проверяет текущий баланс и предупреждение о последствиях.
3. Подтверждает закрытие или отменяет действие.

#### Проверки

- Счёт существует и активен.
- Пользователь явно подтверждает действие.
- Незавершённая форма операции с этим счётом должна быть завершена или отменена.
- Ненулевой баланс не блокирует закрытие, но явно показывается пользователю.

#### Успешный результат

- Счёт становится неактивным.
- Он недоступен для новых операций.
- Исторические операции и рассчитанный баланс сохраняются.
- Остаток счёта продолжает учитываться в общем балансе.

#### Ошибки и восстановление

- При отмене счёт остаётся активным.
- При ошибке сохранения состояние счёта не меняется.
- Если счёт используется в незавершённом вводе, пользователь возвращается к нему для завершения или отмены.
- При необходимости пользователь может снова сделать счёт активным.

### 2.11. Просмотр бюджета с превышением

#### Начальное состояние

- Для бюджета потраченное больше лимита.
- Пользователь видит бюджет на Главной или в списке бюджетов.

#### Шаги пользователя

1. Открывает бюджет с превышением.
2. Проверяет лимит, потраченное и сумму превышения.
3. Просматривает расходы, вошедшие в расчёт.
4. При необходимости открывает конкретную операцию для проверки или редактирования.

#### Проверки

- Превышение рассчитывается как потраченное минус лимит.
- В расчёт входят только расходы нужной категории, валюты и периода.
- Доходы и переводы не учитываются.
- Список операций соответствует показанной сумме потраченного при полностью загруженных данных.

#### Успешный результат

- Пользователь понимает размер превышения и видит операции, которые его сформировали.
- После исправления или удаления ошибочной операции бюджет автоматически пересчитывается.
- После изменения лимита остаток или превышение также пересчитывается.

#### Ошибки и восстановление

- Если часть операций не загружена, итог не обозначается как полный.
- При ошибке загрузки списка сам бюджет остаётся видимым, а список можно загрузить повторно.
- Если операция была удалена, пользователь возвращается к обновлённой карточке бюджета.

## 4. Возврат после сохранения или отмены

| Действие | После успешного сохранения | После отмены |
| --- | --- | --- |
| Создание счёта с Главной | Главная с созданным счётом и предложением продолжить настройку | Пустая Главная |
| Создание или изменение счёта из настроек | Список счетов с актуальными данными | Список счетов без изменений |
| Создание категории из настроек | Список категорий соответствующего вида | Список категорий без изменений |
| Создание категории из формы операции | Исходная форма операции с доступной новой категорией | Исходная форма операции с ранее введёнными данными |
| Создание категории из формы бюджета | Исходная форма бюджета с доступной новой категорией | Исходная форма бюджета с ранее введёнными данными |
| Создание операции с Главной | Главная с обновлённой сводкой | Главная без изменений |
| Создание операции из списка операций | Список операций с новой записью и сохранёнными фильтрами, если новая запись им соответствует | Список операций с прежними фильтрами |
| Создание расхода из бюджета | Карточка бюджета с пересчитанным исполнением | Карточка бюджета без изменений |
| Редактирование операции | Экран, с которого операция была открыта, с обновлёнными данными | Тот же исходный экран без изменений |
| Удаление операции | Экран, с которого операция была открыта, без удалённой записи и с пересчитанными данными | Просмотр операции без изменений |
| Создание бюджета | Список бюджетов с сохранённым выбранным периодом | Список бюджетов с прежним периодом |
| Редактирование бюджета | Карточка бюджета с пересчитанными значениями | Карточка бюджета без изменений |
| Закрытие счёта | Список счетов, где счёт обозначен неактивным | Карточка активного счёта без изменений |

Если исходный экран больше недоступен, возврат выполняется на основной экран соответствующего раздела.

## 5. Обновление данных после финансовых действий

### После создания дохода

- обновляется список операций;
- увеличивается баланс счёта-получателя;
- увеличивается общий баланс соответствующей валюты;
- увеличиваются доходы выбранного периода;
- увеличивается cash flow периода;
- обновляется список последних операций;
- бюджеты расходов не меняются.

### После создания расхода

- обновляется список операций;
- уменьшается баланс счёта-источника;
- уменьшается общий баланс соответствующей валюты;
- увеличиваются расходы периода;
- уменьшается cash flow периода;
- пересчитываются потраченное, остаток, превышение и доля использования связанного бюджета;
- обновляется список последних операций.

### После создания перевода

- обновляется список операций;
- уменьшается баланс исходного счёта;
- увеличивается баланс целевого счёта на ту же сумму;
- обновляется список последних операций;
- общий баланс, доходы, расходы, cash flow и бюджеты не меняются.

### После редактирования операции

1. Из всех расчётов исключается прежнее влияние операции.
2. К расчётам применяется новое влияние операции.
3. Обновляются затронутые счета, валютные итоги, периоды, бюджеты и списки.
4. Если изменён тип операции, пересчёт выполняется по правилам нового типа.

### После удаления операции

- операция удаляется из списков;
- её влияние исключается из балансов затронутых счетов;
- пересчитывается общий баланс соответствующей валюты;
- пересчитываются доходы, расходы и cash flow периода;
- пересчитываются связанные бюджеты;
- обновляется список последних операций.

### После создания или редактирования бюджета

- список бюджетов обновляется;
- потраченное рассчитывается из уже существующих расходов;
- пересчитываются остаток, превышение и доля использования;
- финансовые операции, балансы счетов, общий баланс и cash flow не меняются.

### После изменения начального баланса счёта

- пересчитывается текущий баланс счёта;
- пересчитывается общий баланс соответствующей валюты;
- доходы, расходы, бюджеты и cash flow не меняются, поскольку начальный баланс не является операцией.

### После закрытия счёта

- счёт становится недоступен для новых операций;
- существующие операции и рассчитанный баланс сохраняются;
- остаток продолжает учитываться в общем балансе;
- доходы, расходы, бюджеты и cash flow не пересчитываются только из-за изменения активности счёта.
